# PHACC governs the test stack. It pins Home Assistant core and the whole
# pytest toolchain with `==`, so anything it already pins is listed here
# only if we need a constraint PHACC does not impose.
pytest-homeassistant-custom-component>=0.13.371,<0.14
# PHACC requires Python >=3.14, so validate.yml's tests job tracks 3.14 in
# lockstep; keep the two together when raising the PHACC floor.
# No floors for pytest-asyncio / pytest-cov / pytest-timeout / syrupy.
# PHACC pins all four with `==` (1.4.0 / 7.1.0 / 2.4.0 / 6.1.1 as of
# 0.13.373), so a floor here can never bind: it either matches PHACC and
# does nothing, or contradicts it and makes the install unresolvable.
# pytest.ini's `timeout` setting and `--cov` still work: both plugins
# arrive transitively via PHACC.
# Linters/type-checkers are pinned EXACT (== not >=). ruff and mypy add or change
# rules between releases, so a floating range lets an upstream release turn CI red
# with no code change on your side — brutal on a nightly `schedule` run. Pin them,
# and let upgrades arrive as Dependabot PRs whose CI shows the new findings so you
# adopt them deliberately. Use the version from a working install (`ruff --version`,
# `mypy --version`).
#
# Lesson paid for 2026-07: ruff 0.16.0 floated in and broke every repo's nightly
# CI overnight. The pin is what turned that into a scheduled task instead of an
# outage — 0.16.0 was then adopted deliberately on 2026-07-25, on a branch, with
# its ~80 findings reviewed and fixed. That is the whole point of the `==`: not
# to stay old, but to choose when you move.
mypy==2.4.0
ruff==0.17.0

# point of pinning it. Verify with:

#
# Dependabot is told to ignore it (.github/dependabot.yml). It bumped this to
